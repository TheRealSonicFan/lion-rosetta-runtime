# Rosetta shared-cache validation experiment

## Purpose

This experiment is the next controlled step after the Lion private-dyld run reached the Snow Leopard PowerPC guest dyld and then stopped during guest-library resolution.

The prior Lion run established all of the following:

- the disposable PPC smoke executable is still the validated 32-bit PowerPC binary, with only its `LC_LOAD_DYLINKER` changed to `/usr/oah/dyld`;
- the exact Snow Leopard 10.6.8 dyld is being selected from `/usr/oah/dyld`;
- Lion's native `/usr/lib/dyld` remained unchanged;
- the former Rosetta x86_64-dyld parser crash at `0xc918a01c` was not reproduced;
- the guest dyld found the installed Rosetta shared cache but rejected it because its on-disk libSystem validation did not match Lion;
- after rejecting the cache, guest dyld fell back to Lion's ordinary `/usr/lib/libgcc_s.1.dylib`, which has no PPC slice.

The purpose of this experiment is therefore narrow: determine whether disabling shared-cache file validation for this direct translator process prevents the guest dyld from rejecting the already-installed Snow Leopard Rosetta cache. It is not a proof that the cache contains every guest dependency.

This is a runtime-layer experiment. It does not require another XNU change.

## Safety constraints

Do not alter these constraints during this experiment:

- Do not replace or modify Lion's `/usr/lib/dyld`.
- Do not copy Snow Leopard `libgcc_s.1.dylib`, `libSystem.B.dylib`, or other general system libraries over Lion files.
- Do not rebuild the Rosetta shared cache.
- Do not set `DYLD_SHARED_REGION=private`.
- Do not change the kernel, commpage patch, architecture handler, Rosetta translator, or installed OAH shims.
- Do not run the normal PPC exec path in this step.
- Do not add individual Snow Leopard libraries merely because the previous run named `libgcc_s.1.dylib`; this experiment must first isolate whether the existing validated cache is sufficient.
- Preserve the experiment logs and every newly reported crash/core artifact before making any further change.

The only behavioral change in the test process is `DYLD_SHARED_CACHE_DONT_VALIDATE=1`. `DYLD_PRINT_LIBRARIES=1` is enabled at the same time for observation.

## Exact procedure

Perform the experiment on the Lion 10.7.5 target from the `lion-rosetta-runtime` checkout.

### 1. Update the runtime checkout

```sh
cd /path/to/lion-rosetta-runtime
git pull --ff-only
```

The current runner must contain the guarded cache-bypass mode in `scripts/run-lion-private-dyld-experiment.sh`. It also uses a unique temporary diagnostic marker generated by `mktemp` so newly created crash/core files can be distinguished from prior artifacts.

### 2. Confirm the two private payload files are present

```sh
ls -l \
  ./payload/ppc-smoketest-private-dyld \
  ./payload/snowleopard-10.6.8-dyld
```

Do not substitute rebuilt or newly collected files for this experiment unless their hashes are first incorporated into a separately reviewed test baseline.

### 3. Run only the cache-validation-bypass mode

```sh
ROSETTA_CACHE_BYPASS_VALIDATION=1 \
  ./scripts/run-lion-private-dyld-experiment.sh
```

Do not add other `DYLD_*` variables to this command.

The runner will:

1. require Mac OS X 10.7.5;
2. verify the experimental PPC executable identity and architecture;
3. verify that its `LC_LOAD_DYLINKER` is `/usr/oah/dyld`;
4. verify the private Snow Leopard dyld hash;
5. record the Lion native `/usr/lib/dyld` hash;
6. stage or reuse only the validated private `/usr/oah/dyld`;
7. verify the Rosetta cache and map hashes;
8. audit whether the cache map contains the three guest-library paths above, without treating absence as an identity failure;
9. create a fresh diagnostic marker;
10. launch the direct translator with process-local `DYLD_SHARED_CACHE_DONT_VALIDATE=1` and `DYLD_PRINT_LIBRARIES=1`;
11. capture stdout/stderr and the exit status;
12. list crash reports or core files created after the diagnostic marker; and
13. re-verify the private dyld and Lion native dyld hashes after the run.

The direct execution performed inside the runner is equivalent to:

```sh
DYLD_SHARED_CACHE_DONT_VALIDATE=1 \
DYLD_PRINT_LIBRARIES=1 \
  /usr/libexec/oah/translate ./payload/ppc-smoketest-private-dyld
```

Use the guarded runner rather than executing that equivalent command manually, because the runner supplies the identity, integrity, and diagnostic checks required for this experiment.

## Result interpretation

### PASS

A complete pass requires both:

- the raw output contains the expected `Rosetta PPC smoke test: pid=...` message; and
- the direct translator exits with status 0.

The runner will print `RESULT: PASS`.

A pass establishes that the validated Snow Leopard PPC dyld plus the existing Snow Leopard Rosetta shared cache are sufficient to launch this PPC smoke test on Lion when stale on-disk cache validation is bypassed for the process.

Stop after recording the pass. Do not immediately run the normal PPC exec path. That is a separate layer and must first be tied to the exact running XNU build containing the PowerPC subject-path correction.

### Preflight failure

If the runner stops before the translator because an executable, dyld, cache, map hash, or load-command identity does not match, do not work around the check. Preserve the experiment report and resolve the identity mismatch first.

The earlier run that stopped on `ERROR: validated Rosetta cache map does not list /usr/lib/libgcc_s.1.dylib` exposed a test-script assumption, not an artifact mismatch: the cache and map hashes matched the validated baseline exactly. Because the old runner stopped before launching `translate`, it is expected that only `lion-private-dyld-cache-bypass-experiment.log` exists from that run; no raw direct-translator log could have been created.

### Cache still rejected or the same library remains missing

If the output still says that the shared cache is being ignored, preserve both logs and any new diagnostic artifacts. That means the validation-bypass variable alone is insufficient or is not reaching the relevant guest-dyld path.

If the cache-rejection message disappears but guest dyld still reports `Library not loaded: /usr/lib/libgcc_s.1.dylib`, that is a distinct and expected boundary: the validated Rosetta cache map does not contain that image. Preserve both logs. Do not copy a Snow Leopard library into Lion's `/usr/lib`; the next experiment must use an isolated private-library path.

### Different missing image or different dyld failure

If the cache is accepted but dyld names a different missing image, preserve the exact library trace and fatal diagnostic. Do not immediately satisfy it by copying files. The new path identifies the next runtime boundary and should be reviewed against the validated Rosetta cache map first.

### Crash or trap

If the process terminates by a signal, preserve:

- both cache-bypass logs;
- every crash report listed by the runner; and
- every new core file listed by the runner.

Do not use live GDB or DTrace as the first response; previous Rosetta tests established that those mechanisms perturb this protected translator. Analyze non-debugged diagnostics first.

## Observed Lion result: legacy shared-region syscall boundary

The corrected cache-validation-bypass run reached a new boundary. With `DYLD_SHARED_CACHE_DONT_VALIDATE=1`, guest dyld no longer emitted the stale-libSystem cache rejection and `DYLD_PRINT_LIBRARIES=1` reported the PPC subject as loaded. The direct translator then terminated with status 140. The matching non-debugged crash report identifies `EXC_CRASH (SIGSYS)`, with the crashed thread inside `translate` at `0xb815ac07` and `EAX=0x0000004e`.

This result aligns exactly with a removed Snow Leopard kernel ABI. Apple dyld 132.13 implements its legacy split-segment shared-region operation as:

```c
static int _shared_region_map_np(int fd, uint32_t count,
                                 const shared_file_mapping_np mappings[])
{
    return syscall(295, fd, count, mappings);
}
```

In Snow Leopard XNU 1504.15.3, syscall 295 is `shared_region_map_np(fd, count, mappings)`. In Lion XNU 1699.32.7, syscall 295 is instead `nosys` and is annotated `old shared_region_map_np`; Lion moved shared-cache population to newer interfaces, including syscall 438 `shared_region_map_and_slide_np`.

Lion's `nosys()` sends `SIGSYS` and returns `ENOSYS`. Darwin defines `ENOSYS` as decimal 78, exactly `0x4e`, matching the crash register value. Taken together, the cache-bypass result, SIGSYS exception, EAX value, dyld 132.13 source, and Snow Leopard/Lion syscall-table difference make legacy syscall 295 the leading explanation for this crash.

Do not begin the private-`libgcc_s.1.dylib` experiment yet. The uncached library is no longer the earliest observed boundary once the cache-validation bypass is active.

Before changing XNU, confirm the calling site from the preserved non-debugged `/cores/core.1090`. The authoritative read-only procedure is `docs/postmortem-collector-experiment.md`, using `scripts/collect-lion-shared-region-sigsys-core.sh` to capture runtime-decrypted code around `0xb815ac07`. Live GDB remains unsuitable because Rosetta uses `PT_DENY_ATTACH`.
